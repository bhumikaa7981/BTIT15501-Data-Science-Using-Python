Series & DataFrame

Pandas' two core objects — a labelled column, and a labelled table

💡 Why this exists

A plain Python list only knows position — item 0, item 1... A Series is a list that also knows names (an index), so you can ask for "Banana" instead of "item 1". A DataFrame is just several Series glued side-by-side into a full table. Every row and column carries a label — that's the whole magic of Pandas in one sentence.

🌍 Real-world picture

Open Excel in your head. One column of numbers labelled by row — that's a Series. The entire sheet, Name column + Marks column + Grade column together — that's a DataFrame. You've been using these ideas for years without a Python name for them.

🧠 Syntax Pattern
pd.Series([10, 20, 30])
pd.DataFrame({"name": [...], "marks": [...]})

Getting Data In & Out

Loading real files into Python, and saving your cleaned results back out — the very first and very last line of almost every Pandas program.

📥

Import & Export — Reading Data

How your real project data gets into Python

💡 Why this exists

Nobody types their dataset by hand. Someone hands you a .csv or a .xlsx file, and you need it as a working DataFrame in one line — not fifty. read_csv() and read_excel() are that one line.

🌍 Real-world picture

Every real project starts with loading a sales report or an attendance sheet. This is always the very first working line of code you write.

🧠 Syntax Pattern
pd.read_csv("file.csv")
pd.read_excel("file.xlsx", sheet_name="Sheet1")
🔎 The "Where's my file?" trace — 3 ways to point to a CSV
1
Same folder as your script
Python looks in the current folder first — simplest option.
df = pd.read_csv("student.csv")
2
A different folder — use the full path
Prefix with r so Windows-style backslashes aren't misread as escape codes (\n would otherwise become a newline!).
df = pd.read_csv(
  r"C:\Users\Bhumika\Documents\Data\student.csv"
)
3
Working in Google Colab
Upload the file into the session first, then read it exactly like a local file.
from google.colab import files
uploaded = files.upload()
df = pd.read_csv("student.csv")
📎 Witty takeaway: 90% of "FileNotFoundError" panic is just a path problem. Same folder → plain name. Different folder → full path with r. Colab → upload first.

Selecting & Cleaning Data

Picking exact cells like a surgeon, then handling the gaps that real-world data always, always has.

🎯

Selecting Data — loc, iloc, at, iat

Picking exact rows, columns and cells out of a table

💡 Why this exists

loc selects by LABEL (the name); iloc selects by POSITION (the number), exactly like list slicing. at/iat are their turbo-charged cousins, built for grabbing just one single cell fast.

🌍 Real-world picture

"Give me Aman's marks" is a label lookup — loc. "Give me the 3rd row" is a position lookup — iloc. Like referencing an Excel cell by name (B5) versus counting rows down manually.

🧠 Syntax Pattern
df.loc[row_label, col_label]
df.iloc[row_position, col_position]
df.at[row_label, col_label]     df.iat[row_pos, col_pos]

🎯 Witty takeaway: Name in mind → loc. Number in mind → iloc. Just one cell, need for speed → at/iat.

df.notnull()

Handling Missing Values — Filling

Replacing gaps with a sensible value instead of leaving them blank

💡 Why this exists

fillna() can patch gaps with a fixed value, the column's mean/median, or simply the previous row's value (forward-fill). Picking the right strategy matters — fill wrong, and you quietly bias every calculation that follows.

🌍 Real-world picture

If 3 students didn't report their marks, filling with the class average is far fairer than leaving the cell blank or forcing it to zero (which would tank the whole class's average).

🧠 Syntax Pattern
df.fillna(value)
df["col"].fillna(df["col"].mean())
df.fillna(method="ffill")

Handling Missing Values — Dropping

Sometimes the safest option is to remove incomplete data entirely

💡 Why this exists

dropna() deletes rows (or columns) that contain gaps, instead of guessing a replacement value. axis=0 (default) drops rows; axis=1 drops columns; subset=[...] only checks the columns you name.

🌍 Real-world picture

If a student's entire record — both Name and Marks — is missing, it's safer to drop that row than to guess and fill it with a fake identity.

🧠 Syntax Pattern
df.dropna()
df.dropna(axis=1)
df.dropna(subset=["col"])

🧪 SECTION 4 OF 6

Transforming & Analyzing Data

Filtering, sorting, reshaping and cleaning columns — the toolkit you reach for once your data is already loaded and gap-free.

🔎

Filtering Rows

Asking questions of your table: "show me only…"

💡 Why this exists

Input: a boolean condition → Output: only the rows where that condition is True. Combine multiple conditions with & (and) or | (or) — wrap each condition in its own ( ). isin() checks membership in a list, replacing a long chain of OR conditions.

🌍 Real-world picture

"Show me only students from the IT branch scoring above 80" — exactly how a teacher would shortlist a topper list by hand, just automated.

🧠 Syntax Pattern
df[df["col"] > value]
df[(cond1) & (cond2)]
df[df["col"].isin([...])]
🔎 Witty takeaway: Everything inside df[...] boils down to one question per row: True or False? Keep chaining conditions with &/|, just never forget the parentheses.
↕️

Sorting Data

Asking: "in what order should I look at this?"

💡 Why this exists

Input: column name(s) to sort by → Output: a reordered DataFrame (the original stays unchanged). ascending=False gives highest-first ordering. Sorting by multiple columns uses the second column to break ties in the first.

🌍 Real-world picture

Ranking students by marks to declare a merit list — highest score placed first, exactly like a leaderboard.

🧠 Syntax Pattern
df.sort_values("col", ascending=False)
df.sort_values(["col1","col2"])
df.sort_index()
↕️ Witty takeaway: sort_values() never edits your original table — it hands back a brand-new, reordered one. Forgot the order you started with? sort_index() is your undo button.
⚙️

apply() and map()

Running your own custom logic on every value or every row

💡 Why this exists

apply() runs a custom function on every value (or every row, when axis=1 is used). Input: a function, often a lambda → Output: a new, transformed Series or DataFrame. map() is a lighter tool — ideal for simple value substitution or a dictionary lookup.

🌍 Real-world picture

Converting numeric marks into letter grades (A/B/C) is a rule applied identically to every single student in the table.

🧠 Syntax Pattern
df["col"].apply(function)
df["col"].map({...})
df.apply(function, axis=1)
⚙️ Witty takeaway: Simple lookup or swap → map(). Custom logic, math, or multi-column rules → apply(). Need every row instead of every column? Add axis=1.
✂️

Modifying Columns

drop(), rename(), and creating brand-new columns

💡 Why this exists

drop() removes rows/columns; axis=1 for columns, axis=0 for rows — Output: a smaller DataFrame. rename() relabels columns or rows without ever changing the underlying data values. Assigning to a brand-new column name creates it directly from a calculation.

🌍 Real-world picture

Cleaning up a messy spreadsheet — dropping an unused "Remarks" column, renaming "Stu_Name" to "Name", and adding a computed "Percentage" column.

🧠 Syntax Pattern
df.drop("col", axis=1)
df.rename(columns={"old":"new"})
df["new_col"] = expression
✂️ Witty takeaway: Removing? drop(). Relabelling? rename(). Inventing something new from what's already there? Just assign to a fresh column name — Pandas creates it on the spot.
🔢

Unique Values & Counts

unique(), nunique(), and value_counts()

💡 Why this exists

unique() returns the list of distinct values in a column; nunique() returns their count. value_counts() shows the frequency of each distinct value, sorted highest-first by default.

🌍 Real-world picture

"How many different branches do we have, and how many students belong to each?" — answered instantly with these three tools.

🧠 Syntax Pattern
df["col"].unique()
df["col"].nunique()
df["col"].value_counts()
🔢 Witty takeaway: unique() shows WHAT the categories are, nunique() shows HOW MANY there are, value_counts() shows how POPULAR each one is. Three angles on the same question.
👯

Duplicates

duplicated() and drop_duplicates()

💡 Why this exists

duplicated() flags each row True if it exactly repeats an earlier row. drop_duplicates() removes those repeated rows, always keeping the first occurrence by default. subset=[...] checks duplicates using only specific columns.

🌍 Real-world picture

A student accidentally submits the same registration form twice — duplicated() catches it, drop_duplicates() cleans it up.

🧠 Syntax Pattern
df.duplicated()
df.drop_duplicates()
df.drop_duplicates(subset=["col"])
👯 Witty takeaway: Detect with duplicated() before you destroy anything — then decide with keep="first", "last", or False exactly which copies survive.
🔗 SECTION 5 OF 6

Combining & Summarizing Data

Joining tables together and building group-wise reports — the pattern behind almost every real dashboard.

🔗

Combining Data — concat, merge, join

Bringing two or more DataFrames together into one

💡 Why this exists

concat() stacks DataFrames on top of each other (or side by side) — best for same-structure batches. merge() joins two DataFrames on a shared key column, exactly like a SQL JOIN. join() merges two DataFrames using their index instead of a named key column.

🌍 Real-world picture

Combining January and February attendance sheets (concat), then joining that with a student-details table (merge) to add branch and city for every student.

🧠 Syntax Pattern
pd.concat([df1, df2])
pd.merge(df1, df2, on="id")
df1.join(df2)
🔗 Witty takeaway: Same columns, more rows → concat(). Different tables, shared key column → merge(). Different tables, shared index → join(). Pick based on what actually links them.
📊

Grouping & Pivoting

The single pattern that answers 90% of "summarise my data" questions

💡 Why this exists

groupby() splits rows into groups by a column, ready for a per-group summary calculation. Chain an aggregate — .mean(), .sum(), .count() — right after groupby(). agg() runs several aggregations at once; pivot_table() reshapes data into a summary grid, like an Excel Pivot Table.

🌍 Real-world picture

"Average marks per branch" is a groupby; "average marks per branch, split by gender" is a pivot table.

🧠 Syntax Pattern
df.groupby("col")["target"].mean()
df.groupby("col").agg({...})
pd.pivot_table(df, values="v", index="i", columns="c")
📊 Witty takeaway: groupby() answers "summarise by ONE thing." pivot_table() answers "summarise by TWO things, in a grid." Both are just groupby() wearing a nicer outfit.

REAL-WORLD PROGRAM 1 OF 3

🧩 Student Result Analysis System

Scenario: A college has a CSV of 50 students with Name, Marks and Branch. Some marks are missing. Build one program that loads the data, cleans it, grades every student, and prints a branch-wise summary.

  1. Load students.csv into a DataFrame
  2. Fill missing Marks with the column average
  3. Add a Grade column using apply() + lambda
  4. Filter students who passed (Marks ≥ 40)
  5. Sort passed students by Marks, highest first
  6. Group by Branch to find the average Marks per branch
# --- Runnable end-to-end: builds a small sample dataset in-memory ---
# (swap the pd.DataFrame(...) block below for pd.read_csv("students.csv")
#  once you have the real file)
import pandas as pd
import numpy as np

df = pd.DataFrame({
    "Name":   ["Zoya","Riya","Kabir","Aman","John"],
    "Marks":  [95, 88, np.nan, 35, np.nan],
    "Branch": ["IT","CE","IT","ME","CE"]
})

# Step 1-2: fill missing marks with the column average
df["Marks"] = df["Marks"].fillna(df["Marks"].mean())

# Step 3: derive a letter grade for every student
df["Grade"] = df["Marks"].apply(
    lambda m: "A" if m>=80 else
              ("B" if m>=60 else
              ("C" if m>=40 else "F")))

# Step 4-5: keep only passing students, ranked highest first
passed = df[df["Marks"] >= 40]
ranked = passed.sort_values("Marks", ascending=False)

# Step 6: branch-wise average (calculated on ALL students, pass or fail)
summary = df.groupby("Branch")["Marks"].mean()

print(ranked)
print(summary)

REAL-WORLD PROGRAM 2 OF 3

🧩 Retail Sales Report

Scenario: Two monthly files — sales_jan.csv and sales_feb.csv — need to be combined with a products.csv master list to build a category-wise revenue report.

  1. Load sales_jan.csv and sales_feb.csv
  2. Concatenate both months into a single sales table
  3. Merge sales with products.csv on "product_id"
  4. Create a Revenue column = Quantity × Price
  5. Group by Category and sum the Revenue
  6. Sort categories by total revenue, highest first
# --- Runnable end-to-end: builds sample jan/feb/product tables in-memory ---
# (swap each pd.DataFrame(...) below for pd.read_csv("sales_jan.csv") etc.)
import pandas as pd
import numpy as np

jan = pd.DataFrame({"product_id":[1,2,3], "Quantity":[10,5,8]})
feb = pd.DataFrame({"product_id":[1,2,3], "Quantity":[6,12,4]})
sales = pd.concat([jan, feb], ignore_index=True)

products = pd.DataFrame({
    "product_id": [1, 2, 3],
    "Category":   ["Electronics", "Groceries", "Apparel"],
    "Price":      [15000, 400, 900]
})
merged = pd.merge(sales, products, on="product_id")

# Step 4: revenue for every sale row
merged["Revenue"] = merged["Quantity"] * merged["Price"]

# Step 5-6: total revenue per category, highest first
report = merged.groupby("Category")["Revenue"] \
                .sum().sort_values(ascending=False)

print(report)

Step 3: merge() attaches Category and Price from products using product_id.
Step 4: a new Revenue column is calculated directly from Quantity and Price.
Step 5–6: groupby().sum() totals revenue per category, sort_values() ranks the categories.
REAL-WORLD PROGRAM 3 OF 3

🧩 Employee Data Cleaning Pipeline

Scenario: HR exported an employee list containing duplicate entries and missing departments. Clean it end-to-end before any analysis is done.

  1. Load employees.csv
  2. Detect and count duplicate rows using duplicated()
  3. Remove duplicates using drop_duplicates(subset=["EmpID"])
  4. Fill missing Department values with "Unassigned"
  5. Count employees per department using value_counts()
  6. Export the cleaned file for HR
# --- Runnable end-to-end: builds a sample employee table in-memory ---
# (swap the pd.DataFrame(...) block below for pd.read_csv("employees.csv"))
import pandas as pd
import numpy as np

emp = pd.DataFrame({
    "EmpID":      [101, 102, 103, 101, 104],
    "Name":       ["Aman", "Riya", "John", "Aman", "Zoya"],
    "Department": ["Sales", np.nan, "Engineering", "Sales", np.nan]
})

print("Duplicates found:", emp.duplicated().sum())

# Step 3: keep only the first row per EmpID
emp = emp.drop_duplicates(subset=["EmpID"])

# Step 4: patch missing departments with a clear placeholder
emp["Department"] = emp["Department"].fillna("Unassigned")

# Step 5: headcount per department
print(emp["Department"].value_counts())

# Step 6: write the cleaned file back out for HR
emp.to_csv("employees_clean.csv", index=False)
print("Cleaned file saved.")
